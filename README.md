# astrbot_plugin_touhou_kb

将 `THBWiki` 备用站词条抓取、清洗后导入 AstrBot 官方知识库，并支持会话绑定、人格绑定与东方相关话题的优先知识库路由。

插件本身提供的是“抓取、清洗、导入、路由”能力，不直接附带现成的东方知识内容。安装后，需要先执行初始化或同步命令，把词条导入当前 AstrBot 的官方知识库；导入完成后，模型才能稳定使用这些内容回答相关问题。

## 适用场景

- 想让 AstrBot 更像“懂东方”的人设，优先参考 `THBWiki` 资料回答设定问题。
- 想直接复用 AstrBot 官方知识库，而不是自己额外做一套 RAG 系统。
- 想把知识库绑定到某个会话，或者直接绑定到某个人格，让多个会话共用同一套东方知识。

## 功能概览

- 自动抓取 `https://thbwiki.cc` 的词条页面。
- 自动清洗正文，尽量过滤注释、脚注、导航框、站点装饰内容。
- 单页导入，或核心词条优先、按内容类型和深度受控扩展同步。
- 支持把知识库绑定到当前会话。
- 支持把知识库绑定到人格，供多个会话共享。
- 在东方相关提问时，优先提示 LLM 使用当前知识库，减少先跑 Python、网页搜索之类竞争工具的概率。
- 同步过程会输出 `info` 级日志，方便观察后台抓取和写库进度。

## 安装前提

使用前请先确认：

1. AstrBot 已启用官方知识库功能。
2. 至少已经配置了一个可用的 `Embedding Provider`。
3. 如果想启用重排，可额外配置一个 `Rerank Provider`。
4. AstrBot 所在环境可以访问 `https://thbwiki.cc`。

说明：

- `Embedding Provider` 是必须的，没有它无法创建知识库。
- `Rerank Provider` 是可选的，没有也能用，只是检索排序能力会弱一些。

## 快速开始

推荐按下面的顺序完成首次配置：

1. 安装插件并启用。
2. 打开插件设置，按下面的“插件设置说明”填写配置。
3. 执行 `/东方知识库初始化`
4. 如果知识库还是空的，插件会自动在后台开始同步默认入口词条。
5. 用 `/东方知识库状态` 或 `/东方知识库任务` 观察同步进度。
6. 同步出一定内容后，再根据需要执行：
   - `/东方知识库绑定`
   - `/东方知识库绑定人格`

如果只想先确认插件能正常工作，通常只需要：

- 配好 `Embedding Provider`
- 执行 `/东方知识库初始化`
- 等后台同步完成

## 插件设置说明

建议按下面顺序完成插件设置。

### 1. 基础信息

- `kb_name`
  - 官方知识库名称，默认值为 `东方Project知识库`。
- `kb_description`
  - 知识库描述，用来标识这套知识库的来源和用途。

一般保持默认即可。

### 2. 模型设置

- `default_embedding_provider_id`
  - 默认向量模型 Provider ID。
  - 留空时，会自动选择 AstrBot 当前第一个可用的 Embedding Provider。
  - 如果存在多个 Embedding Provider，建议显式填写，避免后续 provider 顺序变化导致切换。

- `default_rerank_provider_id`
  - 默认重排模型 Provider ID。
  - 留空时，会自动选择 AstrBot 当前第一个可用的 Rerank Provider。
  - 如果当前没有可用的 Rerank Provider，则不会启用 rerank，插件仍可正常工作。

如何查找 Provider ID：

1. 打开 AstrBot 的模型或 Provider 管理页面。
2. 找到你已经配置好的 embedding / rerank 模型。
3. 复制对应的 provider ID，填进插件设置。

建议：

- 只有一个 Embedding Provider 时，`default_embedding_provider_id` 可以留空。
- 有多个 Embedding Provider 时，建议显式填写。
- Rerank 模型还没准备好时，可以先留空，先把知识库跑起来。

### 3. 同步入口与同步规模

- `default_entry_page`
  - 默认入口为 `核心清单`，会先同步分组核心词条；也可改为单个词条或 URL。
- `default_sync_limit`
  - 后台批量同步时，默认最多抓取多少页。

建议：

- 初次使用先保持默认。
- 如果同步结果不错，再手动执行 `/东方知识库同步 核心清单 40` 之类的命令扩充范围。

### 4. 抓取与上传参数

- `request_timeout_sec`
  - 单个页面请求超时时间。
- `crawl_delay_ms`
  - 页面之间的抓取间隔。
- `http_user_agent`
  - 抓取用 UA。
- `http_proxy`
  - 代理地址，留空表示不用代理。
- `pre_chunk_max_chars`
  - 预切片单块最大字符数。
- `pre_chunk_overlap`
  - 预切片块重叠字符数。
- `upload_batch_size`
  - 单次向量化上传的批大小。
- `upload_tasks_limit`
  - 单次文档上传时的并发任务数。

如果使用的 Embedding 服务容易超时或报 `400`，优先把下面两个参数调小：

- `upload_batch_size`
- `upload_tasks_limit`

通常先保持：

- `upload_batch_size = 4`
- `upload_tasks_limit = 1`

会更稳。

### 5. 自动化行为

- `auto_sync_after_init`
  - 初始化后如果知识库为空，是否自动后台同步。
- `auto_bind_after_init`
  - 初始化、导入或同步后，是否自动把当前会话绑定到这个知识库。

说明：

- 知识库本身是全局共享的。
- “自动绑定当前会话”只影响当前聊天，不会修改其他会话。

### 6. 路由相关设置

- `enable_routing_hint`
  - 东方相关话题时，是否给 LLM 注入优先参考知识库的提示。
- `remove_competing_tools`
  - 命中知识库路由时，是否临时移除 Python、网页搜索等竞争工具。

建议默认开启，这样更容易让模型先用知识库回答东方设定问题。

### 7. 噪音过滤

- `sync_exclude_title_keywords`
  - 按标题关键词排除页面。
- `sync_exclude_category_keywords`
  - 按分类关键词排除页面。

默认已经过滤一批比较容易污染设定知识库的页面，比如：

- `LostWord`
- `大炮弹`
- `例大祭`
- `捏他列表`
- 部分现实人物 / 同人画师 / 商业二创手游相关页面

如果希望知识库更偏向“原作设定向”，可以继续补充自己的过滤词。

## 指令

- `/东方知识库初始化 [embedding_provider_id]`
  - 创建或复用知识库；如果知识库还是空的，会自动在后台开始同步默认入口词条。
- `/东方知识库绑定 [top_k]`
  - 把当前会话绑定到东方知识库。
- `/东方知识库绑定人格 [persona_id]`
  - 把指定人格绑定到东方知识库；不传 `persona_id` 时默认绑定当前生效人格。
- `/东方知识库解绑`
  - 把当前会话从东方知识库解绑。
- `/东方知识库解绑人格 [persona_id]`
  - 解除指定人格的东方知识库绑定；不传 `persona_id` 时默认解绑当前生效人格。
- `/东方知识库人格列表`
  - 查看已绑定的人格列表，以及当前会话当前生效的人格。
- `/东方知识库状态`
  - 查看知识库统计、当前会话绑定情况、当前人格绑定情况和最近任务状态。
- `/东方知识库导入 [词条名或URL]`
  - 导入单个词条，默认是 `东方Project`。
- `/东方知识库同步 [入口词条或URL] [页数]`
  - 先抓核心清单或手动入口，再按允许类型扩展；默认最多一层。页数是所有页面共用的请求预算。
- `/东方知识库任务 [task_id]`
  - 查看最近一次或指定任务的同步状态。
- `/东方知识库搜索 [关键词]`
  - 直接测试官方知识库检索结果。

## 推荐使用方式

### 方案一：只给当前群或当前会话用

1. `/东方知识库初始化`
2. 等后台同步一部分内容
3. `/东方知识库绑定`

适合只想在某个群或某个私聊里启用东方知识库的场景。

### 方案二：给某个人格全局使用

1. `/东方知识库初始化`
2. 等同步完成或至少有一部分可用内容
3. `/东方知识库绑定人格 人格ID`

适合多个会话共用同一个东方人设的场景。

### 方案三：持续扩充知识库

1. 先 `/东方知识库初始化`
2. 默认后台同步一轮
3. 再手动执行 `/东方知识库同步 核心清单 40`
4. 需要时补一些单页导入：
   - `/东方知识库导入 博丽灵梦`
   - `/东方知识库导入 红魔乡`

## 日志与排错

同步过程会输出 `info` 级日志，便于确认任务是否正在运行。

你通常能在日志里看到这些阶段：

- 同步任务已创建
- 后台同步开始
- 正在抓取哪个页面
- 哪些页面被跳过，以及跳过原因
- 哪些页面成功写入知识库
- 最终新增 / 更新 / 失败统计

建议直接搜索这些日志关键字：

- `东方知识库`
- `同步任务已创建`
- `后台同步开始`
- `同步写入页面`
- `后台同步完成`

如果初始化失败，优先检查：

1. AstrBot 是否已经配置至少一个可用的 `Embedding Provider`
2. `default_embedding_provider_id` 是否填错
3. `default_rerank_provider_id` 是否填成了不存在的 provider ID
4. AstrBot 机器是否能访问 `https://thbwiki.cc`
5. embedding 服务是否因为批量太大导致超时或报错

如果同步慢、超时多、上传失败较多，优先尝试：

1. 降低 `upload_batch_size`
2. 把 `upload_tasks_limit` 保持为 `1`
3. 适当提高 `request_timeout_sec`
4. 视网络情况设置 `http_proxy`

## 说明

- 默认抓取站点是 `https://thbwiki.cc`。
- 知识来源和站点结构可能发生变化，必要时需要调整清洗规则。
- 这个插件更适合做“东方设定知识增强”，不是严格意义上的全站镜像工具。
- 如果你希望模型更稳定地优先调用东方知识库，建议同时：
  - 打开 `enable_routing_hint`
  - 打开 `remove_competing_tools`
  - 把知识库绑定到常用人格

## 抓取完整性与容量边界

- 解析器按章节提取正文：跳过“注释／参考资料”等章节及其子节，继续处理后续有效章节。支持包装在 `div/section` 中的标题和正文。
- 不再仅因 `noprint/metadata/thumb/gallery` 样式删除整个正文模板；导航、脚本和脚注标记仍会过滤。保留文字不代表会保存图片文件。
- `default_sync_limit` 和同步命令的页数参数是**页面请求次数上限**（包括被排除和失败的页面），最大 500；不是成功导入页数保证。
- `max_page_chunks` 默认 200。单页超限会报告错误，不导入、不截断；已有旧文档保留。需要完整导入大型词条时可提高上限，但应先评估成本。
- 有效重叠字符数不会超过正文块容量的四分之一，避免错误配置让切片数量暴涨。
- 更新词条先上传新版本，成功后才删除旧版本。旧版本删除失败时保留已上传的新版本并明确报错；这不是数据库原子事务，存储故障或进程退出仍需人工检查重复版本。
- 检索失败、检索为空或明确要求联网／搜索／代码时，不移除外部工具。

修复旧数据需要在更新插件后重新导入受影响词条，例如 `/东方知识库导入 博丽灵梦`。修复代码不会自动补齐已有向量内容。

### 是否需要抓全站？

建议按需导入常用角色、作品和设定词条，从 20～40 页起步。核心清单优先于关联链接，关联页仍受请求预算、扩展深度和内容类型限制；启发式分类不能严格区分原作与二创。大型列表、资料汇编可分别手动导入，不建议直接做全站镜像。

容量应看**块数**，而不只是页数。向量原始大小约为：

`块数 × embedding 维度 × 每维字节数`

例如采用 4096 维 float32 向量时，1 万块约 156 MiB，仅为原始向量，不包括索引、稀疏检索、文本和数据库；具体维度取决于服务返回值。假设 40 页、每页 2 万正文字符、每块约 1000 正文字符和约 100 字重叠，约为 900 块、14 MiB 原始向量。这个例子不是实测数据，章节分布和每块来源前缀都会影响实际块数。

预切片内容会直接交给 AstrBot，创建知识库时的 `chunk_size=512` 不会再把这些预切片按 512 切开。`upload_batch_size=4`、`upload_tasks_limit=1` 控制上传峰值，不会减少最终总量。

每轮回答最多由本插件额外注入约 3000 字符，不会塞入整个知识库；会话绑定还可能触发 AstrBot 自身的检索与注入，需在实际部署版本观察是否重复。8B embedding/rerank 模型的推理成本与知识库文件大小是两回事：若自托管，两种模型的内存／显存和推理延迟需要单独评估。

### 当前仍有的设计限制

- 重抓同名页面会重新向量化；尚无内容哈希／修订号增量跳过。频繁全量同步会浪费服务调用。
- 关键词路由可能漏掉别名、代词和连续对话，也没有检索置信度门槛；“返回非空”不代表资料相关。
- 原始 HTML、清洗后的完整正文和清洗版本未独立持久化，排查源站变化与补数据仍需重新抓取。
- URL 重定向和别名尚未统一成稳定的页面 ID，同名判断不能完全解决重复页。
- 当前离线测试不覆盖真实站点反爬、AstrBot 插件加载顺序、Embedding/Rerank 服务和真实检索质量。

## 核心清单与按需补充（0.4）

“常用”首先由维护者指定，不用大模型先分类全站。随附的 19 个词条是可编辑的起始样例，不是全社区热度排名，也不保证覆盖全部原作角色和作品。

| 插件设置 | 作用 |
| --- | --- |
| `core_seed_character` | 核心角色，如博丽灵梦、雾雨魔理沙 |
| `core_seed_work` | 核心作品，如东方红魔乡、东方永夜抄 |
| `core_seed_location` | 核心地点，如博丽神社、红魔馆 |
| `core_seed_organization` | 核心组织，默认空，可自行补充 |
| `core_seed_source` | 原作资料，如东方求闻史纪、东方求闻口授 |
| `sync_max_depth` | 默认 1，设 0 只抓核心／手动入口，最大 3 |
| `sync_allowed_types` | 默认允许角色、作品、地点、组织、原作资料；不含待分类和二创 |
| `max_candidate_records` | 候选记录最多 1000 条，可调至 20～5000 |
| `record_missing_queries` | 是否记录检索为空的问题，默认开启，可关闭 |

各组清单用逗号或换行分隔，支持词条名和本站 URL；清空某一组就不抓该组默认词条。URL 的编码、下划线、www 域名会规范化以减少重复，但重定向别名仍未统一到页面 ID。

收录规则：

1. **核心清单优先**：先将所有核心词条排入队列，再处理关联链接。核心清单和手动入口属于明确选择，除排除规则／未允许的二创外，即使分类不明也可导入。
2. **关联页受控**：从网页分类、清单声明及少量核心资料子页标题推断类型。未知类别默认仅作为候选，不向量化，也不再从该页向外扩展。分类只是规则线索，不是可靠的原作／二创判定器。
3. **排除优先**：标题和分类排除规则仍优先生效，即使在核心清单里也不能绕过。可在设置里明确调整排除词。
4. **同一预算**：所有种子及关联页面共用页数请求上限。必须取回页面才能识别网页分类，所以未导入的候选也可能消耗一次 HTTP 请求，但不会消耗向量化调用。超过深度的链接仅记录，不请求。到达预算不会自动续跑。
5. **保留依据**：候选记录保存内容类型、来源页、深度、处理状态和原因；文本块带类型与核心／按需标记。这些是可读标签，不是 AstrBot 向量索引的结构化过滤字段。

建议操作：

```text
/东方知识库核心清单
/东方知识库同步 核心清单 40
/东方知识库候选
/东方知识库待补充
```

以上清单和记录查看命令仅管理员可用。候选命令可追加 `pending / excluded / imported / failed / all`，默认待确认。每次最多显示 20 条；持久记录超出容量会淘汰最旧项，不删除知识库文档。候选记录只是供维护者选词条的清单，不能当作完整抓取历史。

确认某条值得收录后，可以 `/东方知识库导入 词条名` 单页导入，或将其添加到对应核心组后再次同步。手动单页导入不会继续扩展链接，完成后会更新候选状态。已有知识库不会因调整分类、删除清单条目或缩小深度而自动清理，避免意外删除人工维护内容。

“待补充”仅记录启用绑定、命中东方路由且检索正常返回空文本的问题；服务异常不计入。只保存清洗后的前 200 字、次数和时间，不保存用户／群／会话 ID，最多保留最近 100 个不同问题，按次数展示前 20 项。它可能包含用户问题正文，管理员可 `/东方知识库清空待补充` 清空；关闭 `record_missing_queries` 会停止新记录，已有记录需手动清空。检索非空但不相关、答案错误及连续对话漏路由尚不能自动识别；也不会根据问题自动编造或抓取词条。

升级注意：原有 `default_entry_page` 设置会保留。若仍是 `东方Project`，请改为 `核心清单`，或显式使用上述同步命令。已经非空的知识库不会因升级自动同步，新清单需手动执行一次同步；这不等于部署联调已通过。
